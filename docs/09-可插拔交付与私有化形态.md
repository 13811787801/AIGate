# AIGate-Pro · 可插拔交付与私有化形态

| 项 | 内容 |
|---|---|
| 版本 | V1.0 |
| 日期 | 2026-09-05 |
| 效力 | 产品交付形态决议；与 V4.1 插件架构互补 |
| 主场景 | **企业机房 / 数据中心私有化**（Server + 可选桌面客户端） |

---

## 1. 共识（你提的需求 → 产品定义）

1. **SaaS 能力必须可插拔**：按客户合同增删功能，而不是一套代码硬塞所有人。  
2. **主交付不是公有云 SaaS**，而是：  
   - **Server**：部署在客户机房 / 数据中心（内网）  
   - **Client（可选）**：浏览器控制台，或 **Electron 桌面工具**（给运维/业务同学用）  
3. 公有云多租户 SaaS 只是**可选销售形态**（同一套模块，换部署与计费包装）。

一句话：

> **AIGate = 私有化优先的模块化 AI 网关平台；SaaS 运营能力是插件包，不是核心强依赖。**

---

## 2. 两层「可插拔」

| 层 | 是什么 | 怎么开关 | 谁用 |
|---|---|---|---|
| **A. 产品功能模块（Feature Modules）** | 模型广场、钱包/兑换、报表、SSO、审计、分销… | `config.modules.*` / 许可证包 | 销售按客户勾选 |
| **B. 智能增强插件（Python Plugins）** | 选模、语义缓存、本地分析 | `plugin.enabled` + 独立进程 | 技术增强，fail-open |

A 决定「卖什么功能」；B 决定「智能优化开不开」。两者都可关，**核心网关仍可卖**。

---

## 3. 交付拓扑（企业最常见）

```text
┌──────────────── 客户机房 / 数据中心 ────────────────┐
│                                                    │
│   ┌─────────────┐         ┌──────────────────┐    │
│   │ Electron    │  HTTPS  │  AIGate Server   │    │
│   │ 桌面客户端   │◄───────►│  (Go 单二进制)    │    │
│   │ 或浏览器    │  /v1    │  + 控制台 Web     │    │
│   └─────────────┘         │  + SQLite/MySQL  │    │
│                           └────────┬─────────┘    │
│                                    │              │
│              ┌─────────────────────┼──────────┐   │
│              ▼                     ▼          ▼   │
│         内网 Ollama/vLLM      云厂商 API    可选    │
│         (数据不出公网)         (可选外联)   Py插件  │
└────────────────────────────────────────────────────┘
```

| 角色 | 形态 | 说明 |
|---|---|---|
| Server | `aigate.exe` / Linux 二进制 | 机房部署；OpenAI 兼容 `/v1`；管理 API |
| Client Web | 内嵌于 Server（已有） | 内网浏览器访问 `http://网关:3000` |
| Client Desktop | **Electron 壳（后期 Phase）** | 封装同一套 Web 控制台 + 本地配置向导；适合无浏览器权限的办公机 |
| 业务应用 | SDK / Cursor / 自研系统 | 只认 `Base URL + sk-` |

**Electron 不做第二套业务逻辑**：只做「壳 + 自动发现内网网关 + 证书/代理辅助」。业务 UI 仍来自 Server。

## 4. 功能模块清单（可售卖 SKU）

| 模块 ID | 名称 | 默认私有化 | 说明 |
|---|---|---|---|
| `core` | 核心网关 | **必开** | 鉴权、路由、计费账本、渠道、模型、日志 |
| `console` | Web 控制台 | 默认开 | 管理/用户 UI |
| `marketplace` | 模型广场 | 默认开 | 对外货架展示 |
| `wallet` | 钱包/兑换 | 可关 | 对内核算可开；纯配额企业可关 |
| `playground` | 操练场 | 默认开 | 在线调试 |
| `admin_channels` | 渠道管理 | 默认开 | 管理员 |
| `billing_online` | 在线支付 | 默认关 | SaaS/对外收费才开 |
| `sso` | 企业 SSO | 默认关 | Phase 3+ |
| `audit` | 审计导出 | 默认关 | Phase 3+ |
| `plugin_runtime` | Python 插件运行时 | 默认关 | 增强包 |
| `desktop_client` | Electron 交付包 | 交付物 | 不改 Server 核心 |

销售示例：

- **政企内网包**：`core + console + marketplace + playground + admin`，关 `wallet`/`billing_online`  
- **ISV 转售包**：再开 `wallet` + 兑换码  
- **智能增强包**：再开 `plugin_runtime`  
- **桌面运维包**：加 Electron 安装包指向客户内网 Server

## 5. 工程落地约定（怎么「轻松增删」）

### 5.1 配置开关（当前已落地骨架）

```yaml
modules:
  marketplace: true
  wallet: true
  playground: true
  admin_channels: true
  billing_online: false
  sso: false
  audit: false
  plugin_runtime: false
```

- API：`GET /api/modules`（登录后）返回启用列表  
- 控制台导航按模块隐藏；关闭的模块路由返回 404/403  

### 5.2 代码边界（后续强制）

| 规则 | 要求 |
|---|---|
| 新功能 | 必须挂到某个 `module ID`，禁止散落硬编码 |
| 核心 | `core` 不得依赖可选模块才能编译/运行 |
| 构建 | 可选：用 Go build tag / 分许可证二进制裁剪（后期） |
| 许可证 | Phase 3：签名 license 文件覆盖 `modules.*`（防客户自开未购模块） |

### 5.3 与 Python 插件关系

- `modules.plugin_runtime=false` → 完全不加载插件客户端  
- `=true` 且 `plugin.enabled=true` → 才调用 Python；失败 fail-open

## 6. 阶段规划

| Phase | 交付 |
|---|---|
| **Phase 2（当前）** | 配置级模块开关 + UI 隐藏 + API 暴露；私有化 Server 为主 |
| **Phase 3** | 许可证文件、模块级 API 强制拦截、部署包分 SKU |
| **Phase 4** | Electron 桌面客户端（壳）：连接向导、内网发现、托盘、自动更新（可选） |
| 可选 | 公有云多租户：同一模块体系 + 租户隔离 |

---

## 7. 明确不做什么（防跑偏）

1. **不为 Electron 重写一套后端**。  
2. **不把在线支付做成核心必装**。  
3. **不把「我们是 SaaS 倒卖站」当主叙事**——主叙事是企业机房 AI 中台网关。  
4. 可插拔 ≠ 微服务拆成十几个仓库；**默认仍是单二进制 + 模块开关**，够私有化。
