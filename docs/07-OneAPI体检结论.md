## 结论（决议）

**不整仓 Fork 当 AIGate 主工程。**

采用：

1. **自研 Go 主仓（本仓库）** 按 V4/V4.1 领域模型实现；  
2. **One API 作只读参考**：渠道适配、令牌模型、路由细节对照实现；  
3. 若从 One API **拷贝具体源文件**，必须在 NOTICE 保留 MIT 署名。

### 为什么不整仓 Fork

| 因素 | 说明 |
|---|---|
| 产品目标不同 | One API 偏「中转分发站」；我们偏「企业私有化治理 + 本地模型 + Py 插件」 |
| 计费策略 | 我们强制预扣冻结；直接改上游扣费逻辑成本高、易埋雷 |
| 可控性 | 自研主链路排障路径更清晰，符合「你要能定位问题」 |
| 协议 | MIT 可用，但整仓二开仍要长期跟上游合并冲突 |
