## 0. 先对齐商业分界（持续经营关键）

| 模式 | Admin 是什么 | 防破解怎么抓 |
|---|---|---|
| **onprem 私有化/本地模型** | **客户内部**组织管理：子账户、用量 | 交付许可证锁模块；**不开放**厂商套餐运营台 |
| **saas 连我方 Server** | **我们**的订阅运营台 | **每次登录/API 强校验**；客户端无法本地解锁 |

混用两种 Admin = 商业自杀。工程以 `deploy.mode` + `admin_surface` 强制分流。

---

## 1. 你要的能力（已落地）

1. **Admin 管理 SaaS 可插拔**：套餐（SKU）勾选模块 → 分配给用户。  
2. **按付费用户差异化功能**：用户登录后拿到的是「实例上限 ∩ 套餐」。  
3. **服务端强制校验**：网页 / Electron 只展示；每次 API 重新查库+许可证。  
4. **降低越狱收益**：客户端改 UI / 反编译 **不能** 开通未授权模块（除非攻破服务器或伪造许可证）。

## 2. 权限模型

```text
实例配置 modules.*  ──┐
                       ├─► 实例上限 (ceiling)
签名许可证 license ───┘         │
                                ▼
                         用户套餐 plan.modules
                                │
                                ▼
                      有效权益 entitlements
                    （登录 /session 下发）
                                │
                    每次 API requireModuleFor()
```

| 角色 | 能力 |
|---|---|
| 平台 Admin | 管理套餐/用户；权益=实例上限 |
| 付费用户 | 仅套餐内模块；越权 API → 403 + audit_log |

控制台路径：**套餐与用户**（`/api/admin/plans`、`/api/admin/users`）  
会话路径：`POST /api/auth/login`、`GET /api/session`（Electron 启动后必调）

## 3. 防「AI / 反编译越狱」——能防什么、不能防什么

### 能有效防护（推荐主路径）

| 手段 | 作用 |
|---|---|
| **服务端鉴权** | 改 Electron/网页无效；未授权模块接口直接 403 |
| **JWT 不信任模块声明** | Token 里即使被改 is_admin，服务端仍查 DB `role` |
| **Ed25519 许可证** | 客户无私钥无法伪造合法 license；过期/篡改签名失败 |
| **审计日志** | `module_denied` / 用户变更可追溯 |
| **SaaS 托管你们的 Server** | 客户根本拿不到二进制改服务端逻辑 |

### 无法 100% 防（必须讲清楚）

若客户 **完全掌控私有化 Server 二进制**：

- 理论上可用调试器跳过 `requireModuleFor`（任何本地软件通病）  
- 对策不是「客户端加固」，而是：  
  1. 关键能力放在 **你们可控的线上 License / 激活服务**（可选电话回家）  
  2. 合同 + 序列号绑定机器指纹  
  3. 关键插件 / 模型路由策略不放进客户包  
  4. 法律与停服（SaaS）  

**结论：** Electron 加固、混淆、反 AI 提示词 **都不能当主防线**。主防线 = **权限在服务器判定**。

## 4. 许可证签发（厂商侧）

```powershell
cd AIGate
# 1) 生成密钥对（私钥只留厂商保险柜）
go run ./cmd/licensekit -gen-keys

# 2) 签发客户许可证
go run ./cmd/licensekit -sign -priv "<PRIVATE_B64>" -customer "AcmeCorp" -max-users 100 -out configs/license.json
```

客户 `config.yaml`：

```yaml
license:
  file: "./configs/license.json"
  public_key_b64: "<PUBLIC_B64>"
  require: true   # 生产建议 true
```

## 5. Electron 接入约定

启动后固定流程（不可跳过）：

1. 连接 Server `base_url`  
2. `POST /api/auth/login`  
3. `GET /api/session` → 用 `entitlements.modules` 渲染菜单  
4. 任何业务请求带 JWT；403 则提示升级套餐  

**禁止**在 Electron 本地写「永久解锁」开关。
