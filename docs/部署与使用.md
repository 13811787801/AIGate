# 部署与使用

本文说明如何在 Windows 或 Linux 上运行 AIGate，并完成第一次可用配置。功能说明见 [项目说明书](项目说明书.md)。

## 1. 准备

- Go 1.22 或更高版本。只运行已经编译好的程序时，目标机器不需要安装 Go。
- 一个可写目录，用来放程序、`configs/config.yaml`、`data/` 和 `logs/`。
- 试用默认使用 SQLite，不需要单独安装数据库。多人正式使用时改为 MySQL。

确认 Go：

```text
go version
```

## 2. 配置

在仓库根目录：

```powershell
Copy-Item configs\config.example.yaml configs\config.yaml
```

Linux：

```bash
cp configs/config.example.yaml configs/config.yaml
```

打开 `configs/config.yaml`，至少修改这几项：

| 配置 | 作用 |
|---|---|
| `auth.admin_password` | 首次创建管理员时使用的密码。示例值是 `admin123` |
| `auth.jwt_secret` | 登录令牌签名密钥，换成一长串随机字符 |
| `security.data_key` | 加密渠道密钥的口令，换成另一长串随机字符，之后不要更换 |
| `server.mode` | 本机试用可用 `debug`。正式环境用 `release` |
| `server.host` / `server.port` | 监听地址，默认 `0.0.0.0:3000` |

`release` 模式下，如果 `jwt_secret` 或 `data_key` 仍是示例里的占位值，程序会拒绝启动。

数据库默认是 SQLite：

```yaml
database:
  driver: "sqlite"
  sqlite_path: "./data/aigate.db"
```

改用 MySQL 时：

```yaml
database:
  driver: "mysql"
  dsn: "aigate:STRONG_PASSWORD@tcp(127.0.0.1:3306)/aigate?charset=utf8mb4&parseTime=True&loc=Local"
```

首次启动会自动建表。SQLite 文件不能直接当作 MySQL 的数据文件使用，两边需要各自初始化。已有 `deploy/compose/docker-compose.yml` 可以只启动 MySQL 和 Redis，网关本身仍用上面的二进制运行。

`deploy.mode` 保持 `onprem` 即可用于自己的服务器。`modules` 用来开关模型广场、钱包、操练场等页面；`core` 与控制台始终开启。

## 3. 在 Windows 上运行

开发时直接运行源码：

```powershell
go run .\cmd\aigate -c configs\config.yaml
```

或使用脚本：

```powershell
.\scripts\dev-run.ps1
.\scripts\start-background.ps1
```

`start-background.ps1` 会先编译 `dist\aigate.exe` 再在后台启动。3000 端口已被占用时，它不会再启动第二个进程。

编译 Windows 程序：

```powershell
.\scripts\build-windows.ps1
.\dist\aigate.exe -c configs\config.yaml
```

也可以指定配置路径：环境变量 `AIGATE_CONFIG`，或参数 `-c` / `--config`。

## 4. 编译 Linux 程序

在 Windows 上交叉编译（生成的文件给 Linux x86_64 使用）：

```powershell
$env:CGO_ENABLED = "0"
$env:GOOS = "linux"
$env:GOARCH = "amd64"
$env:GOAMD64 = "v1"
go build -o dist\aigate-linux-amd64 .\cmd\aigate
```

编完后新开一个终端再编译 Windows 版本，避免 `GOOS=linux` 留在当前窗口里。

在 Linux 上本机编译：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 GOAMD64=v1 go build -o aigate-linux-amd64 ./cmd/aigate
```

## 5. 在 Linux 上部署

建议目录：

```text
/opt/aigate/
├── aigate-linux-amd64
├── configs/config.yaml
├── data/
└── logs/
```

```bash
chmod +x aigate-linux-amd64
./aigate-linux-amd64 -c configs/config.yaml
```

升级时只替换 `aigate-linux-amd64`。保留原来的 `configs/config.yaml` 和 `data/`，否则管理员密码、渠道密钥和历史数据会丢失或无法解密。

前台确认正常后，可以用 systemd 或现有的进程管理方式开机启动。监听 `0.0.0.0` 时，请在防火墙里只对需要访问的地址开放 3000 端口。

## 6. 检查是否启动

浏览器打开：

```text
http://127.0.0.1:3000/healthz
```

返回 JSON 即表示进程在监听。控制台地址是：

```text
http://127.0.0.1:3000/
```

从别的机器访问时，把 `127.0.0.1` 换成服务器地址。

## 7. 第一次配置

1. 用 `auth.admin_username` 和 `auth.admin_password` 登录。
2. 进入「渠道管理」，选择厂商，填写该厂商控制台里的 API Key 和接口地址，保存后点测试。
3. 进入「模型管理」，填写对外模型名和上游模型名，设定价格，绑定刚才的渠道并启用。对外模型名不要留空，也不要和已有名称重复。
4. 进入「令牌管理」，创建业务令牌。完整密钥只在创建时显示一次。
5. 打开「操练场」，选择该模型发送一句话。左侧会留下这次会话，之后可以继续同一条对话。
6. 需要联网内容时，勾选「搜索后再回答」。目前仅 DeepSeek 渠道支持。搜索会多消耗上游 token。

渠道和模型保存后都可以再编辑。修改渠道时，密钥框留空表示继续使用原来的密钥。

试用充值可在「钱包管理」兑换 `AIGATE-WELCOME` 或 `AIGATE-DEMO-100`。

## 8. 让别的程序调用

Base URL：

```text
http://<主机>:3000/v1
```

密钥使用第 7 步创建的 AIGate 令牌。

```bash
curl http://127.0.0.1:3000/v1/chat/completions \
  -H "Authorization: Bearer sk-你的令牌" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"你发布的模型名\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}]}"
```

DeepSeek 渠道若这次需要搜索后再回答，在 JSON 中加上 `"web_search": true`。

常见失败：

| 现象 | 处理 |
|---|---|
| 401 | 令牌错误、已停用或已过期 |
| 404 model not found | 模型名与控制台里发布的名称不一致，或模型已下架 |
| 429 | 令牌的每分钟请求数已到上限 |
| 渠道测试失败 | 核对厂商地址、密钥，以及上游实际支持的模型名 |
| 回答说无法联网 | 未开启 `web_search`，或当前渠道不是 DeepSeek |

响应头里的 `X-Trace-Id` 可以到 `logs/aigate.log` 和「使用日志」里对照。

## 9. 备份

备份前先停止程序，然后复制数据文件。SQLite 默认是 `data/aigate.db`；如果旁边有 `aigate.db-wal` 和 `aigate.db-shm`，一起复制。

恢复时同样先停程序，用备份覆盖原文件，再启动。备份必须和使用它的 `security.data_key` 放在一起保管。

MySQL 用逻辑备份：

```bash
mysqldump -h 127.0.0.1 -u aigate -p --single-transaction aigate > aigate.sql
```

恢复：

```bash
mysql -h 127.0.0.1 -u aigate -p aigate < aigate.sql
```

## 10. 日志

默认写入 `./logs/aigate.log`，级别由 `log.level` 控制。排错时先看这条日志里的 trace id，再看令牌是否有效、是否被限流、渠道是否启用、上游是否返回错误。
