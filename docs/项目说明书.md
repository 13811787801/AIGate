# AIGate 项目说明书

AIGate 是一套可以放在自己机器上的 AI API 网关。管理员在网页里接入模型厂商，使用者用统一的 OpenAI 兼容接口调用，不必把厂商密钥交给每一个客户端。

## 适合谁

- 想在内网或自己的服务器上统一接入多家模型的团队
- 需要给不同应用签发独立令牌、限制模型和速率、并记录用量的管理员
- 想先用离线 Mock 把客户端调通，再换成真实厂商的人

## 一次调用怎么走

1. 客户端带着 AIGate 令牌，请求 `POST /v1/chat/completions`。
2. 网关核对令牌、模型权限和速率。
3. 按模型价格预扣余额。
4. 把请求转到已绑定的渠道（厂商或本地服务）。
5. 按实际 token 结算，并写入使用日志。

厂商密钥只保存在网关里，并用 `security.data_key` 加密。客户端只接触 AIGate 自己签发的 `sk-` 令牌。

## 控制台

登录后的页面：

| 页面 | 作用 |
|---|---|
| 数据看板 | 看用量概况 |
| 模型广场 | 看当前可用的对外模型 |
| 操练场 | 多轮对话。左侧是会话列表，可新建、续聊和删除 |
| 令牌管理 | 创建业务密钥，可设置名称、速率、过期时间、可用模型和 IP |
| 使用日志 | 查看调用记录 |
| 钱包管理 | 查看余额，用兑换码充值 |
| 渠道管理 | 添加厂商或本地服务，填写密钥，测试连通，之后也可以修改 |
| 模型管理 | 发布对外模型名、定价，并绑定到某个渠道；已有模型可以编辑 |
| 组织管理 | 私有部署下管理组织内账号 |
| 接入说明 | 控制台里的简短接入提示 |

`deploy.mode` 为 `onprem` 时，管理侧是组织账号和用量。设为 `saas` 时，管理侧改为套餐与订阅。默认示例配置是 `onprem`。

## 对外接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/healthz` | 探活，不需要令牌 |
| GET | `/v1/models` | 列出当前令牌可用的模型 |
| POST | `/v1/chat/completions` | 对话。支持 `stream: true` |

请求头：`Authorization: Bearer <令牌>`。  
Base URL：`http://<主机>:3000/v1`。

请求体与常见 OpenAI Chat Completions 相同，至少包含 `model` 和 `messages`。额外字段 `web_search: true` 表示这次回答前先搜索。该能力目前只对 DeepSeek 渠道生效；操练场里对应的勾选是「搜索后再回答」。未开启时，模型只根据对话内容回答，不会浏览网页。

## 渠道

控制台里可以选择常见厂商，并填入该厂商的 OpenAI 兼容地址。本地的 Ollama 或其他兼容服务，选 Ollama 或「自定义 OpenAI 兼容」即可。Mock 渠道不访问外网，用于确认网关本身是否工作。

连通测试会向该渠道查询可用模型，并选用一个真实模型名试探，不会固定发送无意义的测试名。

## 首次启动会写入的演示数据

库里还没有数据时，程序会创建：

- 配置文件中的管理员账号
- 管理员初始余额 100
- 离线模型 `mock-chat`
- 兑换码 `AIGATE-WELCOME`（10）、`AIGATE-DEMO-100`（100），每个用户各限兑一次

这些兑换码只适合试用。正式使用时请在钱包或数据库中停用，并改掉管理员密码。

## 仓库里有什么

```text
cmd/aigate/       程序入口
internal/         鉴权、渠道、计费、控制台接口
web/              内嵌网页控制台
configs/          配置示例 config.example.yaml
deploy/compose/   可选的 MySQL 与 Redis 容器示例
docs/             本说明书与部署说明
scripts/          Windows 上的编译和启动脚本
```

网页控制台编译进二进制，不需要单独部署前端。

## 配置与数据留在运行机器上

以下内容不进入本仓库：

- `configs/config.yaml`：管理员密码、JWT 密钥、数据加密口令
- `data/`：SQLite 数据库，含渠道密钥密文和对话记录
- `logs/`、`dist/`：日志和编译产物

换机器或恢复备份时，`security.data_key` 必须与当初加密渠道密钥时使用的值相同，否则已保存的厂商密钥无法解密。

## 许可

服务端与网页控制台以仓库根目录的 MIT 许可发布。引用其他开源项目时，保留其许可所要求的署名，不要把 AGPL 许可的源码混入本仓库。
