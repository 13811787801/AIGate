## 1. 先回答你的三个顾虑

### 1.1 Java 21 要不要付费？

**结论：不需要付费。** 你记得的「Java 要收费」，主要指 **Oracle JDK 的商业订阅条款**，不是「Java 语言 / 21 版本本身收费」。

| 发行版 | 是否免费用于生产 | 建议 |
|---|---|---|
| **Eclipse Temurin 21**（Adoptium） | ✅ 免费 | **首选** |
| Amazon Corretto 21 | ✅ 免费 | 可选 |
| Microsoft Build of OpenJDK 21 | ✅ 免费 | 可选 |
| Oracle JDK 21 | ⚠️ 条款复杂，企业生产常需订阅 | **不要用** |

语法方面：从 Java 8 → 17/21，日常业务代码 **90% 写法一样**（类、接口、Spring、MyBatis 几乎不变）。多出来的是 `var`、`record`、`switch` 表达式、文本块等糖，**可以不用**，不影响交付。

难度：若由我主写代码，你主要学「怎么部署、怎么看日志、怎么查配置」，不需要先成为 21 语法专家。

### 1.2 要不要继续用 Java？

结合你的真实约束：

- 私有化交付要简单  
- 你不熟 Docker  
- 出问题要能快速定位  
- 可接受换语言（有人主写）

**最终决议（V1.1 锁定）：**

1. **Go**：主网关与控制台后端（鉴权、限流、计费、渠道路由、日志、本地/云上游）。  
2. **Python**：**后期插件**（模型挑选、缓存、本地语义分析等）；主链路不依赖它。  
3. **本地大模型**：作为 `openai_compatible` 渠道接入（Ollama / vLLM / Xinference 等），可与云渠道混合路由。  
4. 不以 Java 为首期主栈（保留备用）。

原因一句话：

> Go 保证私有化「好装、好扛、好查」；Python 保证智能优化「能演进」；本地模型保证数据可不出公网。

### 1.3 Docker 会不会成为门槛？

**决议：Docker 为可选项，不是上线前提。**

交付分两档：

1. **A 档（默认教你）**：Windows / Linux 直接跑二进制或安装包 + MySQL/SQLite，不强制 Docker  
2. **B 档（后期）**：客户机房已有 Docker 再给 `compose.yml`

你先会 A，再学 B。

## 2. 技术选型最终决议

### 2.1 选型表

| 层级 | 选型 | 为什么 |
|---|---|---|
| 产品对标 | One API / TokenHub 使用逻辑 | 市场已验证 |
| 开源起点 | **One API（MIT）** 优先评估落地；禁止默认用 New API（AGPL）做闭源商用 | 协议可商用 |
| 主后端 | **Go 1.22+** | 单二进制、并发网关、好部署 |
| 智能插件 | **Python 3.11+**（后期；可打包成独立进程） | 选模/语义缓存/本地分析生态好 |
| 插件通信 | HTTP JSON（先）；失败 fail-open | 好排障；主链路可降级 |
| 上游类型 | 云 API + **本地 OpenAI 兼容推理** | 政企内网刚需 |
| 前端 | React/Vue（随底座） | 管理台+用户台 |
| 数据库 | **SQLite（试用）→ MySQL 8（正式）** | 先易后难 |
| 缓存 | Redis（可关） | 限流/精确缓存 |
| 部署 | **无 Docker 可运行**；Compose 可选 | 降低运维门槛 |
| 观测 | 日志文件 + traceId + 控制台日志页 | 快速定位 |

### 2.2 明确放弃 / 后置

| 项 | 决定 |
|---|---|
| 全站 Java 为首期唯一路径 | 后置备用 |
| New API（AGPL）闭源商用底座 | ❌ 禁止（除非商业许可） |
| 强制 Docker | ❌ 禁止 |
| 首期就上语义缓存/选模插件 | ❌ 后置（Phase 4+）；Go 先预留 Hook |
| 首期双栈强依赖（无 Py 不能跑） | ❌ 禁止 |

### 2.3 本地模型与插件（V1.1 新增）

- **本地模型**：管理台可配置内网 Base URL；支持「本地优先、云兜底」。  
- **Python 插件**：独立进程；`fail_open=true` 时插件挂了网关仍可用。  
- 详细契约见 `架构补丁-V4.1-Go与Python插件.md`。

### 2.4 B 计划（备用）

One API 二开不可行时：Go 按 V4 领域模型自研；产品能力对齐，不改「Go 主 + Py 插件」总方向。

## 3. 系统架构（排查问题用这张图）

```text
客户应用 / Cursor / SDK
        │ Bearer sk-xxx
        ▼
┌─────────────────────────────────────────────┐
│         AIGate Core（Go，必须有）              │
│  鉴权 → 限流 → [可选插件] → 渠道路由 → 计费     │
└───────────┬───────────────────┬─────────────┘
            │                   │
            ▼                   ▼
   ┌────────────────┐   ┌──────────────────┐
   │ 云渠道          │   │ 本地渠道           │
   │ DeepSeek/通义…  │   │ Ollama/vLLM/内网  │
   └────────────────┘   └──────────────────┘

后期可选：Python 插件进程（选模 / 缓存 / 语义分析）
         失败 → 自动降级，不影响主网关
```

### 3.1 你要记住的核心对象

| 对象 | 是什么 | 出问题先查哪 |
|---|---|---|
| **User** | 企业内账号 | 是否禁用、余额是否为 0 |
| **ApiKey（令牌）** | `sk-` 开头访问密钥 | 是否过期、模型白名单、IP 限制 |
| **Channel（渠道）** | 云或**本地**上游地址 + Key | Base URL、本地服务是否存活、上游 Key |
| **Model** | 对外模型名 | 是否映射到可用渠道（可多条） |
| **Group** | 计费倍率组 | 倍率是否异常 |
| **Plugin（后期）** | Python 增强进程 | 是否启用、超时、能否 fail-open |

### 3.2 一次请求怎么走（排障顺序）

1. 有没有 `traceId`？  
2. ApiKey / 限流 / 模型权限？  
3. 若启用插件：日志里是命中、跳过还是降级？  
4. 命中的是**本地渠道还是云渠道**？  
5. 本地：先 `curl 内网/v1/models`；云：查上游 Key/额度  
6. 扣费：看日志 token 与倍率  
7. 进程 / DB / 磁盘  

**铁律：主链路不依赖 Python；插件有问题先关插件再查。**

## 5. 部署形态规范（你要学的最小集）

### 5.1 最小可运行（推荐先学）

**组件只有 2～3 个：**

1. `aigate.exe`（或 Linux `aigate`）——主程序  
2. `config.yaml` 或环境变量 ——数据库地址、管理员密码、端口  
3. MySQL（正式）或自动 SQLite（试用）

启动后访问：

- 控制台：`http://服务器IP:端口`  
- API：`http://服务器IP:端口/v1/chat/completions`

### 5.2 你需要掌握的命令级技能（Windows）

| 技能 | 做什么 | 对应排障 |
|---|---|---|
| 看进程是否在跑 | 任务管理器 / `Get-Process` | 服务挂了没 |
| 看端口是否监听 | `netstat -ano | findstr 3000` | 端口冲突 |
| 看日志文件 | `logs\aigate.log` | 报错原文 |
| 改配置重启 | 改 yaml → 停进程 → 再启动 | 配置不生效 |
| 备份数据库 | 导出 MySQL / 拷贝 sqlite 文件 | 误删可回滚 |

### 5.3 Docker（后学，不必怕）

你只需理解三句话：

1. 镜像 = 装好的软件包  
2. 容器 = 跑起来的一个实例  
3. `docker compose up -d` = 按清单一次性拉起程序+数据库  

等无 Docker 路径你跑顺后，再学这一档。

## 7. 学习路径（给你的，按周）

### 第 1 周：不写代码，只学会「装起来、打通一次 API」

1. 会启动 / 停止服务  
2. 会登录管理台  
3. 会加渠道、建令牌  
4. 会用 curl 或 Apifox 调 `/v1/chat/completions`  
5. 会在日志里找到一次失败原因  

### 第 2 周：学会排障树

按本文件 **§3.2** 做 5 个故障演练（我后续给脚本）：

- Key 错误  
- 余额不足  
- 上游 Key 失效  
- 模型名写错  
- 限流触发  

### 第 3 周：可选学 Docker

只学：安装 Docker Desktop → `compose up` → `compose logs` → `compose down`。
