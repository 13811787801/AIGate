# AIGate-Pro · 数据库备份与恢复手册

| 项 | 内容 |
|---|---|
| 版本 | V1.0 |
| 日期 | 2026-09-07 |
| 适用 | `database.driver=sqlite` / `mysql` |
| 关联 | `configs/config.example.yaml` · M3 生产硬化 |

## 1. 选型建议

| 场景 | 驱动 | 说明 |
|---|---|---|
| 本机开发 / 快速 PoC | **sqlite** | 默认；单文件，零依赖 |
| 客户机房正式交付 / 多写并发 | **mysql** | InnoDB；建议独立备份账号 |

切换示例（`configs/config.yaml`）：

```yaml
database:
  driver: "mysql"
  dsn: "aigate:STRONG_PASSWORD@tcp(127.0.0.1:3306)/aigate?charset=utf8mb4&parseTime=True&loc=Local"
```

首次启动会自动建表（含 `` `user` `` 等）。**不要**把 SQLite 文件直接拷进 MySQL——两边需各自初始化，或走导出/导入迁移（见 §4）。

## 2. SQLite 备份与恢复

默认路径：`./data/aigate.db`（可用 `database.sqlite_path` 覆盖）。

### 2.1 热备份（推荐）

进程可在线时用 SQLite Online Backup API；Windows 最简单可靠做法：

1. **停服**（或至少停止写入窗口）  
2. 复制文件：

```powershell
# 在仓库根目录
New-Item -ItemType Directory -Force -Path .\backups | Out-Null
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item .\data\aigate.db ".\backups\aigate-$ts.db"
# 若存在 WAL/SHM，一并拷贝
Copy-Item .\data\aigate.db-wal ".\backups\aigate-$ts.db-wal" -ErrorAction SilentlyContinue
Copy-Item .\data\aigate.db-shm ".\backups\aigate-$ts.db-shm" -ErrorAction SilentlyContinue
```

3. 校验：`sqlite3 backups\aigate-....db "PRAGMA integrity_check;"`（有 CLI 时）

### 2.2 恢复

1. 停服  
2. 用备份覆盖 `database.sqlite_path` 指向的文件（含 `-wal`/`-shm` 若备份时有）  
3. 启动，访问 `/healthz` 与控制台登录

### 2.3 注意

- 仅拷贝 `.db` 而线上仍有未 checkpoint 的 WAL，可能丢最近写入——**停服后拷贝最稳**。  
- 备份文件与 `security.data_key` 配套：渠道 Key 密文换机后需同一 `data_key` 才能解密。

## 3. MySQL 备份与恢复

假设库名 `aigate`、用户 `aigate`。

### 3.1 逻辑备份（mysqldump）

```powershell
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
New-Item -ItemType Directory -Force -Path .\backups | Out-Null
mysqldump -h 127.0.0.1 -u aigate -p --single-transaction --routines --triggers aigate `
  > ".\backups\aigate-$ts.sql"
```

`--single-transaction` 适合 InnoDB，尽量少锁表。

### 3.2 恢复

```powershell
# 停服后执行
mysql -h 127.0.0.1 -u aigate -p aigate < .\backups\aigate-YYYYMMDD-HHMMSS.sql
```

空库恢复：先 `CREATE DATABASE aigate CHARACTER SET utf8mb4;`，再导入。

### 3.3 生产建议

- 每日自动 dump + 异地留存（对象存储/另一台机）  
- 保留至少 7 份日备 + 1 份周备  
- 定期做**恢复演练**（别只备份不练）  
- 账号最小权限：应用账号勿用 `root`；备份可用只读+`LOCK TABLES` 或 dump 专用账号

## 4. SQLite → MySQL 迁移（概要）

当前**无**一键迁移工具。推荐路径：

1. 新环境用 `driver=mysql` 启动，自动建空表并 seed 管理员  
2. 业务数据按表导出（渠道/模型/用户/Key）后手工或脚本导入  
3. API Key 只存哈希：用户侧需重新发放 Key，或从旧库迁移 `api_key` 行  
4. 渠道 `api_key_enc`：同一 `security.data_key` 可原样迁密文字段  

PoC 阶段可接受「新库 seed + 重新配渠道」。

## 5. 验收清单

| 检查 | 期望 |
|---|---|
| sqlite 停服拷贝后启动 | 登录与调用记录仍在 |
| mysql dump 后恢复到空库 | 表齐全，admin 可登录 |
| 更换 `data_key` 后读旧密文渠道 | 解密失败（预期）；改回原 key 恢复 |

## 6. 相关配置字段

```yaml
database:
  driver: "sqlite"          # 或 mysql
  sqlite_path: "./data/aigate.db"
  dsn: ""                   # mysql 时必填
security:
  data_key: "..."           # 与备份一起保管，否则渠道密文无法解密
```
