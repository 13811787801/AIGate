## 1. 评审结论（先看这里）

### 1.1 总评

| 维度 | 结论 |
|---|---|
| **M2 范围符合性** | **有条件通过（Conditional Pass）** |
| **产品方向 / 架构合理性** | **通过（Pass）** — 双模式分界正确，是可持续经营的关键设计 |
| **可否对外宣称「可售卖成品 SaaS」** | **否** — 无在线支付、生产级密钥保管、MySQL/高可用未就绪 |
| **可否对外宣称「私有化试点可演示」** | **是** — 主路径（网关+控制台+组织管理+Mock）已闭环 |

**一句话：**  
设计方向对、商业分界清楚、核心链路可跑；作为 **M2 试点/演示基线** 可以冻结并备案，但必须带「条件清单」进入下一阶段，**不得夸大成已商业化闭环产品**。

### 1.2 门禁建议

| 建议动作 | 说明 |
|---|---|
| ✅ **冻结 M2 基线** | 以 docs/12 为变更回溯基准 |

| ⚠️ **不开放公网付费订阅销售** | 待 M3：支付 + AES + saas 生产 hardening |
| 📋 **进入 M3 前必须关闭的条件项** | 见 §5 |

## 2. 设计合理性评审（产品 / 架构）

### 2.1 做得对的地方（应保持）

| # | 设计点 | 评审意见 |
|---|---|---|
| 1 | **onprem vs saas 双模式 Admin 分界** | **优秀**。私有化只做组织治理、线上才做套餐强校验，直接对应「持续经营」；混成一种 Admin 会毁掉订阅收入模型。 |
| 2 | **服务端权益判定（requireModuleFor）** | **正确**。客户端/Electron 只展示，鉴权在 Server，符合防破解主路径。 |
| 3 | **Go 单二进制 + 嵌入控制台** | **适合私有化交付**。降低运维门槛，符合「无 Docker 可跑」决议。 |
| 4 | **OpenAI 兼容协议作为统一对外契约** | **市场已验证**。业务侧迁移成本低。 |
| 5 | **本地模型 = 渠道，而非第二套产品** | **合理**。避免产品线膨胀。 |
| 6 | **计费冻结→结算/解冻** | **方向正确**，降低透支风险（实现完整度见风险）。 |
| 7 | **需求备案 docs/12 + REQ/TC 编号** | **项目管理合格**。后续变更可回溯。 |

### 2.2 设计上需警惕的点（不是否定，是管控）

| # | 风险点 | 严重度 | 说明与建议 |
|---|---|---|---|
| 1 | onprem 客户掌控 Server 二进制仍可 patch | 中（已知） | 文档已声明；**收入不要押在「防客户改自己机器」**；押在 saas 托管与合同授权。 |
| 2 | 厂商列表映射到统一 `openai_compatible` | 中 | Claude/Gemini 等若非兼容端点会「看起来能配、实际不通」。UI 需持续标注「需官方兼容端点」。 |
| 3 | 默认 admin 密码 / 开发 JWT secret | 高（交付前） | 试点包必须强制修改；建议首次启动强提示。 |
| 4 | 渠道 Key 明文入库 | 高（生产） | 已标 Phase3；**试点可接受，生产不可接受**。 |
| 5 | Phase1 `X-Admin-Token=admin_password` 引导接口仍在 | 中 | 与 JWT 管理并存，扩大攻击面；M3 应收口或关默认。 |
| 6 | 操练场依赖「用户已有 API Key」 | 低 | UX 不完整；应用户无 Key 时自动引导创建。 |
| 7 | saas 模式抽检不足（本次默认 onprem） | 中 | 结论对 saas 为「设计已落地、验收未全量」——见 §3。 |

### 2.3 架构评分（满分 5）

| 项 | 分 | 评语 |
|---|---|---|
| 产品边界清晰度 | 5 | 双模式 + Out of Scope 写得清楚 |
| 技术选型匹配交付场景 | 4.5 | Go+SQLite 匹配 PoC；生产需 MySQL |
| 安全与商业模式匹配 | 4 | 线上路径对；落库加密与支付未齐 |
| 可演进性（模块/插件） | 4 | 模块开关有；Python 插件仅占位 |
| 文档与可验收性 | 4.5 | REQ/TC 齐全；自动化测试套件仍缺 |

**设计综合：4.3 / 5 — 合理，可继续加码，不必推倒重来。**

## 5. 有条件通过 — 条件清单（进入下一阶段前）

以下为验收负责人开出的 **Must / Should**：

### 5.1 Must（发布试点包前）

1. **强制修改** `admin_password` / `jwt_secret`（文档+启动警告）。  
2. **发布说明**写明：渠道 Key 明文存储；仅内网试点。  
3. **补跑一次 saas 模式切换验收**（TC-MODE-05/06/07）并附结果到变更单。  
4. 对外话术统一为：**「M2 私有化可演示网关」**，禁止「完整商业化 SaaS」。

### 5.2 Should（M3 优先）

1. 渠道 Key AES；关闭或鉴权收紧 Phase1 bootstrap admin。  
2. 操练场无 Key 时一键创建引导。  
3. 厂商下拉对非兼容协议加风险提示。  
4. entitlements + billing 核心单测。  
5. MySQL 接线与备份手册。

### 5.3 Could（体验）

1. 组织用量按时间范围筛选。  
2. 审计日志只读页。  
3. 真实云厂商一键验收脚本（自备 Key）。
